# Anvil 开发详细计划

**配套文档：** [项目描述](./项目描述.md) · [方案总览](./AI-Agent-Workbench-Plan.md)  
**假设：** 1 名全职开发者（可与 Agent 结对）；Windows；Node 22+；已能在本机使用 Pi 或至少能安装 `@earendil-works/pi-coding-agent`。  
**默认拍板：** 产品名 Anvil；MVP = 本机 Web + Node Host；开发用 SDK、发布用 RPC；先树后多 Agent。  
**工作方式：** 每个 Phase 有入口条件、任务包、验收清单、明确不做。未通过阶段门，禁止开始下一阶段。

---

## 0. 怎么用这份计划

### 0.1 进度单位

- **Phase**：有完成标准的阶段门
- **Week**：日历周，按单人全职估算
- **WP（Work Package）**：可在 0.5–2 天内完成的任务包
- **验收**：可勾选的用户可见结果，不是「代码写了」

### 0.2 优先级

| 标记 | 含义 |
|---|---|
| P0 | 不做则阶段失败 |
| P1 | 强烈建议，可在阶段末尾若超时则砍 |
| P2 | 显式推迟，写入下阶段或冰盒 |

超时策略：**砍 P1，不扩 P0。** 禁止用「再加两天」破坏阶段门。

### 0.3 每日节奏（dogfood 开始后）

1. 用 Anvil 自己改 Anvil（Phase 1 通过后强制）
2. 先修阻断缺陷，再做新 WP
3. 每天结束：Host 能启动、Web 能连上、至少一条路径可演示

### 0.4 工具与命令约定

```bash
pnpm install
pnpm dev            # 并行启动 host + web
pnpm --filter host check
pnpm --filter web  check
pnpm test
```

开发期 Web 默认 `http://127.0.0.1:5173`，Host `http://127.0.0.1:4317`（端口可改，写入 `.anvil-dev.json`，不要抢 3080；Windows 上 4310 常被 QQ 占用）。


## 2. 仓库与工程基线（Phase 0 内完成）

目标结构：

```
anvil/
  package.json                 pnpm workspace 根
  pnpm-workspace.yaml
  tsconfig.base.json
  .gitignore
  AGENTS.md                    给人类和 Agent 的开发约定
  apps/
    host/                      Node Host
    web/                       Vite + React
    desktop/                   空目录 + README（Phase 4 再用）
  packages/
    protocol/                  共享类型 + Zod schema
    ui/                        后期抽设计系统，Phase 0 可暂放 web 内
    pi-ext-gate/
    pi-ext-delegate/
    pi-ext-artifact/
  docs/
    项目描述.md
    开发计划.md
    AI-Agent-Workbench-Plan.md
    rfc/                       阶段内 RFC（可选）
```

根脚本：

| script | 作用 |
|---|---|
| `dev` | `pnpm -r --parallel dev` |
| `check` | 所有包 typecheck + lint |
| `test` | Vitest |
| `build` | 各包 build |

`.gitignore` 至少排除：`node_modules`、`dist`、`.env`、`*.sqlite`、真实 session、`.anvil/`。

`AGENTS.md` 最少写清：

- 不改 Pi session 格式
- UI 不准直接碰 FS / 密钥
- 新能力优先 Pi Extension
- 协议变更必须改 `packages/protocol` 并双边编译通过

## 3. Phase 0 · 骨架（Week 1，3–5 天）

### 3.1 目标

浏览器打开就能看到 **假对话流、假工具卡、假状态栏**。不接真模型。证明：monorepo、协议、WS、三栏布局能跑。

### 3.2 入口条件

- 本机 Node 22+
- 已阅读 [项目描述](./项目描述.md) 第 5–9 节
- 产品名与 MVP 形态已按默认值或用户指定执行

### 3.3 任务包

#### WP-0.1 初始化 monorepo　P0　0.5 天

- pnpm workspace、tsconfig、gitignore、基础 README
- `apps/host` `apps/web` `packages/protocol` 空包能 `pnpm install`

**验收：** `pnpm install` 一次成功；三个包都有 `package.json`。

#### WP-0.2 协议包　P0　0.5 天

在 `packages/protocol` 定义：

- 12 个 Phase 1 命令的 TypeScript 类型 + Zod
- `AnvilEvent` 联合类型
- `Request / Response / Event` 信封：

```ts
{ id: string, kind: "req" | "res" | "ev", type: string, payload: unknown }
```

**验收：** 从 host 和 web 都能 import 同一类型；改一个字段两边编译失败（这是好事）。

#### WP-0.3 Host 骨架　P0　1 天

- 原生 `http` 或轻框架（推荐 `hono` + `@hono/node-server`，避免 Express 历史包袱）
- `GET /health` → `{ ok: true, version }`
- WebSocket `/ws`
- 心跳 15s
- 内存态 `WorkspaceState`
- `FakePiAdapter`：`prompt()` 后按时钟推一组假事件（text_delta → tool/start → tool/end → idle）

**验收：** `curl localhost:4310/health` 成功；用简易 WS 客户端能收到假事件。

#### WP-0.4 Web 骨架　P0　1.5 天

- Vite + React + Tailwind + 基础布局
- 三栏：左会话占位、中消息列表、右检查器占位、底 Composer、顶状态栏
- WS 客户端：连上、断线提示、重连
- 把假事件渲染成气泡 + 一张假 `bash` 工具卡
- Composer 发送 → `agent.prompt`

**验收：** `pnpm dev` 后浏览器能发「你好」，1 秒内出现假回复和假工具卡。

#### WP-0.5 开发体验　P1　0.5 天

- 根 README：如何启动
- `AGENTS.md` 初稿
- Host 请求日志（脱敏）
- 统一端口与 CORS（仅 localhost）

**验收：** 按 README 从零启动不超过 5 分钟（不含 pnpm 下载）。

### 3.4 本阶段明确不做

- 真 Pi、真模型、真文件树
- Electron
- 登录、主题、动画
- 设计系统抽包（组件先写在 `apps/web`）

### 3.5 阶段门（全部勾上才能进 Phase 1）

- [x] `pnpm dev` 一键起 host + web
- [x] 浏览器可见三栏和状态栏
- [x] 发送一条消息能走完假 Agent 循环
- [x] 刷新页面后 WS 重连（此时可丢失假状态，Phase 1 再做快照）
- [x] `pnpm check` 通过
- [x] 文档：README 启动说明

### 3.6 风险

Vite 代理与 WS 路径搞错 → 第一天就写死 `/ws` 协议与端口常量，放 `packages/protocol`。

## 4. Phase 1 · MVP 结对（Week 2–4）

### 4.1 目标

你能用 Anvil 打开本机仓库，让 **真 Pi** 改代码：过程可看、可停、可审批、可恢复会话。

### 4.2 入口条件

Phase 0 阶段门全部通过。本机至少配置好一个 Pi 可用的模型（环境变量或 `pi /login`）。

### 4.3 周计划

| 周 | 焦点 | 结束时应能演示 |
|---|---|---|
| Week 2 | 工作区 + 真 Pi SDK 接通 | 选定文件夹后，真模型能回复（可先只读工具） |
| Week 3 | 工具卡 + 审批 + 会话 resume | bash 被拦截，点允许后执行；关掉再打开能 resume |
| Week 4 | 打磨 + 状态栏费用 + 缺陷 | 用 Anvil 改 Anvil 完成一个小 PR 级改动 |

### 4.4 任务包

#### WP-1.1 工作区打开　P0　1 天

- `workspace.open { path }`
- 校验路径存在、是目录
- 记录最近项目（`~/.anvil/config.json`）
- 信任状态：`untrusted | trusted`，默认 untrusted
- UI：打开文件夹对话框走 Host（浏览器版用输入路径 + 浏览列表；原生对话框 Phase 4）

**验收：** 输入 `F:\adfadda\demo2342\demooo` 后状态栏显示该 cwd；重启 Host 后最近项目还在。

**浏览器限制：** 网页不能调系统文件对话框。Phase 1 用「粘贴路径」+ Host `fs.tree` 预览。README 写清楚。

#### WP-1.2 Pi SDK Adapter　P0　2 天

- 依赖钉死：`@earendil-works/pi-coding-agent` 精确版本
- `SdkAdapter` 实现 `PiAdapter`
- 使用 `createAgentSessionRuntime()`；cwd 变化必须重建 runtime
- 订阅原始事件 → 映射 `AnvilEvent`
- `FakePiAdapter` 保留，用环境变量 `ANVIL_FAKE_PI=1` 切换（CI 默认假）

**验收：** 信任项目中发「列出当前目录文件」，真模型调用 `read`/`bash` 或等价工具，UI 出现真实结果。  
**失败回退：** SDK API 与文档不一致时，先写 `docs/rfc/pi-sdk-notes.md` 记录实际 API，再改 adapter，禁止把 Pi 类型抄进 UI。

#### WP-1.3 会话列表 / new / resume　P0　1.5 天

- 扫描 Pi 在该 cwd 下的 session 文件（按 Pi 实际目录，常见为项目内或 `~/.pi`，以 SDK 为准，禁止猜）
- `session.list` 返回 id、标题、mtime、token 汇总（没有就空）
- `session.new` / `session.resume`
- runtime 替换后 **必须** 退订旧 session、订阅新 session
- 左侧会话列表，当前项高亮

**验收：** 新建两条会话，切换后消息不串；resume 官方 `pi` 刚用过的会话，历史能出现在 Anvil（若格式字段需转换，只允许只读映射）。

#### WP-1.4 流式消息 UI　P0　1.5 天

- `message/upsert` 驱动列表
- assistant 文本流式追加
- 用户消息立即上屏
- 列表自动滚到底，用户上翻则停止自动滚
- 长消息折叠（超过 N 行）
- Markdown 渲染（只读，注意 XSS：用 rehype-sanitize）

**验收：** 一次超过 20 行的回复可流畅滚动；刷新后（WP-1.8）能还原。

#### WP-1.5 工具卡　P0　1 天

- `tool/start|update|end` → 卡片
- 运行中显示 spinner 与已用时
- 展开看参数与输出
- 失败态红色 + 错误文本
- 输出过长截断，可「展开全部」

**验收：** 一次 `bash git status` 能看到完整 stdout。

#### WP-1.6 审批闸门扩展　P0　2 天

- `packages/pi-ext-gate`
- `beforeToolCall`：
  - untrusted：拦截 write/edit/bash
  - protectedPaths：拦截
  - bash 默认 ask
  - 永远 ask：`rm -rf`、`git push`、`git reset --hard`
- 拦截时向 Host 发审批请求，挂起 Promise，直到 `approval.respond`
- UI 模态/右栏审批卡：允许一次 / 拒绝
- 超时（默认 5 分钟）视为拒绝

**验收：**

1. 未信任仓库发「删除 node_modules」→ 不能执行
2. 已信任仓库发 `git status` → 弹出审批 → 允许后有输出
3. 拒绝后 Agent 收到失败 tool result，而不是 Host 崩溃

#### WP-1.7 Steer / Follow-up / Abort　P0　1 天

- Composer 在 `agent/running` 时显示两个按钮：插入方向 / 结束后做
- `Esc`：先 `clear_queue`（若 SDK 有等价 API；没有则只 abort）再 abort，输入框恢复队列文本
- 发送中禁止重复 prompt（按钮 disabled），除非显式 steer/follow-up

**验收：** 模型跑工具时发 steer，能在下一轮 LLM 前改变方向；Esc 立刻停，且不丢输入。

#### WP-1.8 快照重连　P0　1 天

- Host 维护当前 UI 快照：会话 id、消息、工具、审批、usage、agent 状态
- WS 连接后先推 `snapshot`，再推增量
- 快照只在内存；Host 重启允许丢失运行态，但 session 文件仍在

**验收：** 跑到一半刷新浏览器，消息和工具卡还在；进行中的 tool 状态合理（running 或已结束，不许永久转圈）。

#### WP-1.9 模型列表与切换　P0　1 天

- `model.list` 来自 Pi 已配置 providers，不要自造目录
- `model.set`
- Composer 上方下拉
- 无模型：中文空状态，说明去设 `ANTHROPIC_API_KEY` / `DEEPSEEK_API_KEY` / 跑 `pi` 登录

**验收：** 能从列表切换模型，下一轮 prompt 用新模型；状态栏显示当前模型。

#### WP-1.10 状态栏用量　P1　0.5 天

- tokens 输入/输出、cache 若 Pi 有就显示、粗算 cost（没有价格表就只显示 tokens）
- `usage/update` 事件

**验收：** 一轮对话后数字增加，不回零（除非新会话）。

#### WP-1.11 只读文件树　P1　1 天

- `fs.tree`：一层一层展开，忽略 `node_modules/.git/dist`
- 点击文件：Host 读文本（限制大小 512KB、限制二进制）在右栏或简单预览
- 不提供保存

**验收：** 能浏览本仓库并打开 `docs/项目描述.md`。

#### WP-1.12 中文与空状态　P0　0.5 天

- 所有按钮、错误、空状态中文
- 首次进入三张启动卡片（解释仓库 / 修 bug / 恢复会话）——第三张若无历史则禁用

**验收：** 不出现英文框架报错直接甩给用户（底层 exception 可放「详情」折叠）。

#### WP-1.13 测试与钉版本　P0　1 天

- Vitest：protocol Zod 样例
- FakeAdapter 集成测试：prompt → 事件序
- gate：对危险命令返回 ask/deny 的单元测试（纯函数抽出策略）
- CI 可选；至少本地 `pnpm test` 绿
- lockfile 提交；Pi 包 exact version

**验收：** 不连网也能跑测试（假 adapter）。

#### WP-1.14 Dogfood 小改动　P0　0.5 天

用 Anvil 给 README 加一节「常见问题」。过程截图或会话文件留在 `docs/dogfood/phase1.md`（可脱敏）。

**验收：** 阶段回顾里能指出 3 个真实摩擦点。

### 4.5 本阶段明确不做

- 会话树可视化（列表够用）
- Diff 视图、PTY 终端、命令面板、`@` 补全
- 多 Agent、看板、Electron
- hunk 接受、自动 commit
- 自造 OAuth

### 4.6 阶段门

- [x] 打开真实仓库路径（浏览器粘贴路径 + Host 校验）
- [x] 未信任模式下无法 bash / write（闸门纯函数 + FakeAdapter 覆盖）
- [x] 已信任模式下 bash 可审批通过
- [x] 新开会话、恢复会话、切换会话（id = Pi jsonl 路径）
- [x] 刷新浏览器推 snapshot
- [x] Esc / 中止能停，并 clearQueue
- [x] 官方 `pi` 能 resume Anvil 产生的 session（假循环/子任务写出带 assistant 的 jsonl；SessionManager.open 抽检）
- [ ] 用 Anvil 完成一次 dogfood 改动（需真模型）
- [x] `pnpm check && pnpm test` 绿

### 4.7 风险与减载

| 若超时 | 砍掉 |
|---|---|
| SDK 对接超过 3 天 | 文件树、用量金额、启动卡片动画 |
| 审批难做 | 先做「全盘 ask bash + write」，allowlist 推 Phase 2 |
| resume 目录搞不清 | 先只支持 Anvil 自己创建的 session，官方 session 导入标 P1 |

## 5. Phase 2 · 树与制品（Week 5–6）

### 5.1 目标

同一问题能分叉两条方案并切换；能看本轮文件变更；人有自己的终端。

### 5.2 入口条件

Phase 1 阶段门通过；dogfood 摩擦点已记入冰盒或本阶段 WP。

### 5.3 周计划

| 周 | 焦点 | 演示 |
|---|---|---|
| Week 5 | 会话树 + fork/navigate + compact | 两条分支来回切，对话跟着变 |
| Week 6 | 快照 Diff + PTY + 命令面板 | 看 Agent 改了哪些文件；自己能敲 `git diff` |

### 5.4 任务包

#### WP-2.1 树数据与 `tree/changed`　P0　1 天

- 从 Pi session 解析树（按官方 session format，见 Pi `session-format` 文档）
- 规范化为 `TreeNode { id, parentId, summary, status, usage }`
- 每次 turn_end / fork 推 `tree/changed`

**验收：** 假数据下 UI 能画 10 节点树；真 session 能出节点。

#### WP-2.2 树视图　P0　2 天

- 横向树（可用简易 HTML/SVG，不必上大图形库；节点多再换）
- 单击高亮、双击 `tree.navigate`
- 右键：Fork / 从这里继续 / 复制节点 id
- 当前分支高亮
- 失败/压缩态

**验收：** 双击历史节点后主对话只显示该分支；再 fork 出新节点。

#### WP-2.3 `session.fork` / `navigateTree`　P0　1 天

- 封装 SDK：`runtime.fork` 与 `session.navigateTree`
- 导航时若 Agent 忙：拒绝并中文提示「等当前轮结束」
- fork 后切到新 session 或同文件新分支（以 Pi 语义为准，adapter 对齐，UI 不猜）

**验收：** 对同一句用户消息 fork 两次，得到两段不同回复，互不覆盖。

#### WP-2.4 compact　P1　0.5 天

- 按钮「压缩上下文」
- 完成后树节点标记 compressed，检查器显示摘要

**验收：** 长会话 compact 后下一轮仍能工作；官方 `pi` 能打开。

#### WP-2.5 快照扩展 `pi-ext-artifact`　P0　1.5 天

- write/edit 前复制原文件，后复制新文件到 `.anvil/artifacts/snapshots/<turn>/<path>`
- 推 `fs/changed`
- 保护：不快照二进制大文件（>2MB 只记 hash）

**验收：** Agent 改一个 ts 文件后，artifacts 里能 diff 出前后。

#### WP-2.6 Diff 视图　P0　1.5 天

- 列表：本轮变更文件
- 只读 unified diff
- 操作：整文件还原（用快照）
- 同时尝试显示 `git diff`（无 git 则仅快照）

**验收：** 能看出 Agent 改了哪几行；点还原后工作区文件回去（git 干净或回到快照）。

#### WP-2.7 人用终端　P1　1.5 天

- Host 用 `node-pty`（Windows 用 ConPTY）
- 独立于 Agent bash
- xterm.js 前端
- 只在 trusted 项目启用
- 关闭面板即杀进程

**验收：** 在 Anvil 里跑 `git status` 和 `pnpm test`（若耗时长可 Ctrl+C）。

**减载：** Windows 上 node-pty 编译失败则本 WP 整包推迟到 Phase 4，阶段门不卡它。

#### WP-2.8 命令面板 + `@文件`　P1　1.5 天

- `Ctrl+K`：命令、会话、文件
- Composer `@` 触发文件模糊搜（Host 提供搜索，限制结果 50 条）
- 选中后插入相对路径

**验收：** `@开发计划` 能命中 `docs/开发计划.md` 并随 prompt 发送。

#### WP-2.9 `/` 命令透传　P1　0.5 天

- 输入 `/` 列出 Pi 命令/skills/templates（能拿到列表就做，拿不到就当普通文本）
- 不要重写 Pi 命令系统

**验收：** Composer 输入 `/` 列出 `/compact` `/new` `/abort` 并触发对应协议命令。没有项目 skill 时不当普通文本吞掉斜杠。

## 6. Phase 3 · 多 Agent（Week 7–9）

### 6.1 目标

主 Agent 能把任务委派给最多 N 个子会话（建议并发 2），深度 1，结果摘要写回；UI 有任务托盘。

### 6.2 入口条件

Phase 2 阶段门通过；文件锁设计 RFC 写在 `docs/rfc/file-lock.md`（可一页）。

### 6.3 周计划

| 周 | 焦点 | 演示 |
|---|---|---|
| Week 7 | delegate 扩展 + Host 拉起子 runtime | 主会话能开一个只读子会话并收回摘要 |
| Week 8 | 并发、文件锁、超时、花费上限 | 两个实现者改不同目录 |
| Week 9 | 三角色 + 托盘打磨 + dogfood | 「加一个小功能」全流程 |

### 6.4 任务包

#### WP-3.1 `delegate_task` 扩展　P0　2 天

工具参数：

```ts
{
  goal: string
  persona: "architect" | "implementer" | "reviewer" | string
  cwd?: string          // 必须是工作区内相对路径
  tools?: string[]
  timeoutSec?: number
  maxUsd?: number
}
```

- 扩展只发请求给 Host，不自己 spawn 无限循环
- Host 创建子 `PiAdapter`，`parentSession` 指向父
- 子会话 system prompt 注入目标、边界、禁止再 delegate

**验收：** 单测：非法 cwd（逃出工作区）被拒。

#### WP-3.2 子会话生命周期　P0　2 天

- 状态：queued / running / waiting_approval / succeeded / failed / cancelled
- 超时 abort
- 花费超限 abort
- 完成后生成摘要（子会话最后让模型写 20 行以内总结 + 文件列表）
- 摘要作为 tool result 回父会话

**验收：** 父会话能根据摘要继续说话；子会话可在侧栏单独打开。

#### WP-3.3 文件锁　P0　1 天

- Host 维护 `path → taskId`
- 子任务开始时根据即将编辑的 glob 预锁（或在 write/edit 时抢锁）
- 冲突：tool 失败信息「文件被任务 X 锁定」
- 任务结束释放

**验收：** 两个实现者同时写同一文件，第二个失败而不是混写。

#### WP-3.4 深度与扇出限制　P0　0.5 天

- 子会话工具列表去掉 `delegate_task`
- 全局并发上限 2（可配置）
- 超出排队

**验收：** 子 Agent 试图再委派 → 无该工具或调用被拒。

#### WP-3.5 任务托盘 UI　P0　1.5 天

- 底部或左侧「运行中」
- 每条：persona、goal 截断、状态、耗时、费用
- 点击打开子会话对话
- 完成横幅（不打断主 Composer）

**验收：** 两个子任务并行时托盘同时更新，不卡 UI。

#### WP-3.6 内置角色　P1　1 天

- `~/.anvil/personas/` 三份默认 markdown/json
- 项目 `.anvil/settings.json` 可覆盖工具集
- 架构师默认只读 + delegate
- 实现者默认全工具
- 审查者只读、无 bash

**验收：** 不配模型也能按角色限制工具（用假 adapter 测）。

#### WP-3.7 审批继承　P1　1 天

- 子会话 bash 同样走闸门
- UI 审批卡标明来自哪个子任务
- untrusted 项目禁止 delegate 出可写子会话

**验收：** 子任务危险命令弹卡，拒绝后只有该子任务失败。

#### WP-3.8 Composer `@agent:`　P1　0.5 天

- `@agent:审查者 看这段 diff` 转成对主会话的明确指令或直接开子任务
- v1 允许简单：插入提示文本，让主 Agent 去 delegate（少做魔法）

**验收：** 用户能从输入框点名角色。

#### WP-3.9 可观测　P1　0.5 天

- 父+子费用汇总
- 失败分类：超时 / 超费 / 锁冲突 / 模型错误 / 用户拒绝

**验收：** 一次失败在检查器里能看到原因，不是只说「error」。

#### WP-3.10 Dogfood　P0　1 天

任务：「给 Host 加一个 `/metrics` 健康扩展字段」。要求主会话拆前端文案 + Host 实现 + 审查。记录于 `docs/dogfood/phase3.md`。

### 6.5 本阶段明确不做

- 深度 > 1
- 看板
- 自动合并子分支 git
- 共享向量记忆

### 6.6 阶段门

- [x] 主会话成功委派 2 个子任务（假编排 + 托盘）
- [x] 深度 1 被强制
- [x] 写同一文件会锁冲突
- [x] 子会话可单独打开，且是合法 Pi jsonl（SessionManager.create + parentSession）
- [x] 未信任项目不能派出可写子 Agent
- [x] dogfood 任务闭环（离线：两个只读子任务各自跑 FakePiAdapter 并写 jsonl；真模型需密钥）
- [x] 官方 `pi` 仍能打开父/子会话（jsonl 由 SessionManager 写出）

### 6.7 减载

`@agent` 语法砍掉，改用托盘「新子任务」按钮。  
角色配置砍到硬编码三个。  
并发降到 1（串行委派）——仍算通过，但文档标明限制。

## 7. Phase 4 · 产品化（Week 10–12）

### 7.1 目标

别人能装、高风险仓库能沙箱、有看板、有安装包或至少有一键脚本。

### 7.2 任务包（按优先级排，12 周不够就停在 P0）

#### WP-4.1 RPC Adapter　P0　2 天

**验收：** Host 启动探测 Docker；没有则设置页只显示说明，不阻断。本机未验证进容器。

#### WP-4.5 桌面壳　P1　2 天

**验收：** `pnpm --filter desktop dev` 加载 5173；系统文件夹对话框走 preload IPC。开发版仍需本机 Node。

#### WP-4.6 Windows 安装体验　P1　1.5 天

**验收：** 在一台干净 Windows 上按文档 15 分钟内看到 UI（不含模型密钥申请）。

#### WP-4.8 hunk Diff　P2　2 天

## 11. 人员与分工（单人默认）

若变成 2 人，建议切分 **不要按文件随机切**，按进程边界：

| 人 | 负责 | 不负责 |
|---|---|---|
| A Host/协议/Pi adapter/扩展 | 安全、会话、编排 | 视觉细节 |
| B Web/UX | 布局、卡片、树、面板 | 直接调 Pi SDK |

接口就是 `packages/protocol`。一人请假，另一人仍能对着协议 mock 开发。

单人时顺序永远是：**协议 → Host/Fake → UI → 真 Adapter**。禁止先画完 UI 再倒逼协议。
