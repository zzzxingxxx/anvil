# Anvil 项目描述

**产品暂名：** Anvil（铁砧）  
**一句话：** 以 Earendil Pi 为引擎的本地优先 Agent 工作台——人负责目标、分叉、审批与编排，Pi 负责读改代码与工具循环，Anvil 负责把这一切变成可观察、可控制、可协作的操作系统。  
**形态：** Windows 优先 · 本地优先 · 中文优先 · 不 fork Pi · 不重写 Agent Runtime  
**当前仓库：** `F:\adfadda\demo2342\demooo`  
**配套文档：** [方案总览](./AI-Agent-Workbench-Plan.md) · [开发计划](./开发计划.md)

---

## 1. 项目是什么

Anvil 是一个跑在本机的 **AI Agent 工作台（Workbench）**，不是聊天机器人，也不是又一个 VS Code 插件。

用户打开一个代码仓库，Anvil 在本地拉起 Pi Agent。之后所有「思考、读文件、改文件、跑命令」都由 Pi 完成；Anvil 提供：

- 看清 Agent 正在做什么（对话、工具卡、树、Diff、费用）
- 在关键动作上踩刹车（审批、只读、沙箱）
- 把一次探索拆成多条分支、多个角色、多条子任务
- 把过程沉淀成可恢复的会话和可交付的制品

对用户来说，Anvil 是 **Agent IDE / 指挥中心**。  
对 Pi 来说，Anvil 是 **宿主（Host）+ 一组官方机制上的扩展**。

### 1.1 不是什么

| 不是 | 原因 |
|---|---|
| 不是 Pi 的 fork | Pi 迭代快，fork 会永久落后 |
| 不是 OpenPi 的中文套壳 | 皮肤没有存在理由 |
| 不是云端多租户 SaaS | 代码、密钥、命令必须留在本机 |
| 不是完整 IDE | 不替代 VS Code；深度编辑仍用原编辑器 |
| 不是通用 ChatGPT 客户端 | 只服务「对着仓库干活」 |
| 不是全自动运维机器人 | 不默认改生产、推远程、删仓库 |

### 1.2 和「直接用终端 Pi」的关系

终端里的 `pi` 已经很好。Anvil 存在是因为终端做不好这些事：

- 同时盯多个会话、多条分支、多个子 Agent
- 把工具调用渲染成可审批的卡片
- 把文件变更做成可视化 Diff
- 给不熟的仓库加信任边界
- 用中文工作台把「会话 / 树 / 制品 / 看板」放在同一块屏幕上

**硬约束：** Anvil 不发明私有 session 格式。会话文件仍是 Pi 的 jsonl。关掉 Anvil，用官方 `pi` 必须能 resume。

## 2. 为什么现在做

### 2.1 引擎已经成熟

Pi（[pi.dev](https://pi.dev)，包名 `@earendil-works/pi-coding-agent`）把最不该自研的部分做完了：

- 多厂商模型（Anthropic / OpenAI / DeepSeek / Gemini / OpenRouter / llama.cpp …）
- Agent 循环、工具调用、事件流
- 会话树、分叉、compaction
- Extensions / Skills / Prompt Templates / Themes / Pi Packages
- 四种嵌入方式：交互、print/JSON、**RPC**、**SDK**

Pi 的设计哲学是 **核心刻意做小**：默认只有 `read / write / edit / bash`，子 Agent、Plan Mode、权限系统故意不做，留给宿主和扩展。这正好是工作台的产品空间。

### 2.2 现有 GUI 没有把空白填满

| 产品 | 它已经做了 | 它没做或做弱的 |
|---|---|---|
| OpenPi | Electron 壳、sidecar、Git/Diff/终端 | 会话偏线性；编排弱；中文与 Windows 不是一等公民 |
| PiX | 非线性会话树、多列对比 | 工作流、多 Agent、制品、审批弱 |
| pi-workbench | Kanban / DAG 叙事 | 早期，完成度低 |
| EnsoCode / Nerve / Bivor | 各有切口 | 不是 Windows + 中文 + 编排的完整解 |

**Anvil 的存在理由必须同时成立三点：**

1. 树状会话是一等公民（吸收 PiX，而不是附属可视化）
2. 多 Agent 编排是一等公民（Pi 官方空白）
3. 制品 + 审批 + 权限是一等公民（Pi 无内置权限，既是风险也是产品）

一句话：**OpenPi 是 Pi 的桌面皮肤；Anvil 是 Pi 的操作系统。**

### 2.3 首发用户就是作者自己

第一版不为「所有开发者」设计，为 **Windows 上同时开多个仓库、又要用 Agent 干活、又不能把仓库交给黑盒** 的个人全栈开发者设计。自己用不起来，就不给别人装。

## 3. 目标与非目标

### 3.1 项目目标

1. **可日常使用：** 关闭终端 Pi，日常改本仓库都能在 Anvil 里完成。
2. **可控制：** 危险命令、保护路径、不信任仓库，默认要人点头。
3. **可分叉：** 同一问题能保留多条探索路径，上下文跟随分支。
4. **可编排：** 主 Agent 能把任务委派给有限深度的子 Agent，结果可检视。
5. **可离开：** 数据是 Pi 会话 + git + 普通文件，不被 Anvil 锁死。
6. **可观察：** 每次 tool call、模型切换、token 与费用都能点开看。

### 3.2 成功标准

**四周（个人 dogfood）**

- 用 Anvil 完成一次真实功能开发（读代码、改代码、跑测试、看 diff）
- 至少一次从树节点分叉对比两种实现
- 没有出现「Agent 偷偷跑了危险命令」

**三个月（可演示）**

- 「给这个仓库加一项能力」能拆成 2–3 个子任务并行，审查者只读提意见
- 外人 `pnpm i && pnpm dev`，10 分钟内跑通一次真实会话
- 同一会话用官方 `pi` 仍能 resume

### 3.3 明确不做（v1）

- 云同步、账号体系、团队权限、计费
- 内置完整代码编辑器（Monaco 最多只读预览）
- 自动 commit / push / 发 PR（可后期做成 skill，默认关闭）
- 无限层级 Agent 联邦、共享可变记忆总线
- 移动端、浏览器远程控制本机
- 自研 LLM 网关、自研 tool loop、自研 session 格式

## 4. 用户与场景

### 4.1 用户画像

**P0 自己**

- Windows 主力开发机
- 同时维护多个本地仓库
- 已能接受 Agent 改代码，但不能接受它静默 `rm` / `git push` / 读 `.env`
- 需要中文界面和中文错误信息

**P1 同类个人开发者（三个月后）**

- 已经在用 Claude Code / Cursor / 终端 Pi
- 觉得「聊天窗不够，IDE 又太重」
- 愿意为本机软件装 Node 22

**P2 不做**

- 非技术用户
- 要「一键生成 App」的人
- 企业采购流程用户（暂无 SSO、审计导出合规包）

### 4.2 核心场景

**场景 A · 单仓库结对编程（Phase 1 必须跑通）**

1. 打开文件夹  
2. 选择模型（复用 Pi 已登录的 provider）  
3. 用中文说目标  
4. 看流式回复和工具卡  
5. bash / 写保护路径时弹出审批  
6. 看变更，继续或停止  
7. 关闭后再打开，会话还在

**场景 B · 分叉探索（Phase 2）**

同一 bug 试「改算法」和「改数据结构」两条路。树上看得到两条分支，对话面板只显示当前分支，失败的那条留着以后回来。

**场景 C · 主从协作（Phase 3）**

用户对主 Agent 说「给这个仓库加登录」。主 Agent（架构师）拆任务：

- 实现者 A：改后端，cwd 限定 `apps/host`
- 实现者 B：改前端，cwd 限定 `apps/web`
- 审查者：只读，出一份问题清单

主会话只收回摘要和变更文件列表，不把整段 transcript 灌回去。

**场景 D · 带审批的长任务（Phase 1 起步，Phase 4 加固）**

Agent 想执行 `git reset --hard` 或读取 `.env`：卡片红标，必须人点「允许一次 / 拒绝」。允许本会话、命令前缀白名单是后续。

**场景 E · 失败回放**

某次工具调用把测试跑红了。用户从该节点 fork，换一种修法。原路径完整保留。

### 4.3 用户旅程（第一次打开）

```
启动 Anvil
  → 空状态：选择文件夹 / 打开最近项目
  → 未信任仓库：只读预览，询问是否信任
  → 检测已有 Pi sessions，可 resume
  → 无密钥：中文说明去哪配置（环境变量或 Pi /login），不自造 OAuth
  → 三张启动卡片：
      「解释这个仓库」
      「修这个 bug」
      「从树里恢复上次会话」
  → 进入三栏工作台
```

## 5. 产品原则

1. **Pi 拥有 Agent 语义。** 会话树、compaction、tool loop、extensions、providers 全部走 Pi。
2. **UI 只渲染，不碰特权。** 浏览器/渲染进程不能直接读盘、开 shell、碰密钥。
3. **Host 拥有桌面权力。** 信任策略、PTY、Git、密钥、沙箱、进程监督在 Host。
4. **扩展走 Pi 官方机制。** 新能力优先写成 Extension / Skill / Package，离开 Anvil 仍可用。
5. **默认可观察。** 没有「后台偷偷发生」的 tool call。
6. **默认要人在回路。** 高风险默认 Ask，可按项目放宽。
7. **中文是一等公民。** 界面、空状态、快捷键、错误信息中文；系统提示词中英双轨。
8. **会话可携带。** jsonl 兼容是硬指标，破坏它等于发布事故。
9. **宁少勿滥。** 一个能天天用的结对工作台，好过半成品操作系统。

## 6. 信息架构与界面

### 6.1 总体布局

```
┌──────────────┬───────────────────────────────┬────────────────────┐
│ 工作区       │ 主舞台                         │ 检查器             │
│              │                               │                    │
│ 项目         │ 视图切换：                     │ 当前节点           │
│ 会话列表     │  对话 | 树 | Diff | 终端      │ 工具时间线         │
│ 角色         │       | 制品 | 看板            │ Token / 费用       │
│ 运行中任务   │                               │ 队列 / 模型 / 权限 │
│              │ 底部 Composer                  │                    │
└──────────────┴───────────────────────────────┴────────────────────┘
顶栏：命令面板入口、模型、思考等级、信任状态
底栏：cwd · session · tokens ↑↓ · cache · cost · model · 连接状态
```

### 6.2 左侧工作区

| 对象 | 含义 | 信任/生命周期 |
|---|---|---|
| 项目 Workspace | 一个文件夹或 git 仓库 | 一个信任边界 |
| 会话 Session | 一份真实 Pi jsonl | 随 Pi SessionManager |
| 角色 Persona | system + tools + skills + 默认模型 | `~/.anvil/personas` + 项目覆盖 |
| 运行中 | 主会话与子任务的活状态 | Host 进程内 |

### 6.3 主舞台六视图

| 视图 | 用户在干什么 | 数据来源 | 首次出现 |
|---|---|---|---|
| 对话 | 看当前分支的消息和工具卡 | Pi 事件 | Phase 1 |
| 会话树 | 分叉、跳转、对比入口 | Pi session tree | Phase 2 |
| Diff | 看/接受/还原本轮文件变更 | 快照 + git | Phase 2 |
| 终端 | 人自己敲命令 | Host PTY，与 Agent bash 隔离 | Phase 2 |
| 制品 | 打开报告、补丁、导出 | `.anvil/artifacts/` | Phase 2 |
| 工作流看板 | 卡片=子会话，列=状态 | 编排层 | Phase 4 |

Phase 1 只做对话 + 最简文件树只读预览。其余视图可以有入口，但标「即将到来」，不要做假交互。

### 6.4 Composer（驾驶舱）

Composer 不是普通输入框。

| 能力 | Phase |
|---|---|
| 纯文本发送 | 1 |
| 流式中 Steer / Follow-up | 1 |
| Esc = 清队列 + abort，文本还回输入框 | 1 |
| 模型、思考等级、只读/可写开关（输入框上方） | 1 |
| `@文件` 模糊搜索 | 2 |
| `/` 调 Pi 命令、skills、templates | 2 |
| `@agent:审查者` 显式点名委派 | 3 |
| 粘贴图片 | 3（Pi 已支持 images） |

Steer：当前这轮工具跑完、下一次 LLM 调用前插入。  
Follow-up：Agent 整轮停下来再发。  
二者语义必须与 [Pi RPC](https://pi.dev/docs/latest/rpc) 一致，不能自己发明第三种队列。

### 6.5 工具卡片

每条 tool call 一张可折叠卡：

- 标题：`edit src/app.ts` / `bash pnpm test`
- 状态：排队 / 待审批 / 运行 / 成功 / 失败
- 展开：参数、stdout/stderr、diff hunk
- 操作（v1）：允许一次 / 拒绝  
- 后期：允许本会话、编辑后再跑

审批卡必须让人在 **不看原始 JSON** 的情况下判断风险。

### 6.6 会话树

- 横向生长；节点 = 一轮 user + assistant + tools
- 单击高亮（不切面板）
- 双击：主对话对齐到该节点
- 右键：Fork / 从这里继续 / 克隆分支 / 复制摘要
- 失败节点红、压缩节点灰
- 后期：最多 3 列并排钉住不同分支（学 PiX，不做 v1）

这是 Pi 已有 branching 的可视化，不是新格式。

### 6.7 命令面板

`Ctrl+K` 统一搜：命令、会话、文件、角色、模型。专家用户的主入口。Phase 2 上线。

## 8. 技术架构

### 8.1 总览

```
┌──────────────────────────────────────────┐
│  apps/web  Vite + React                  │
│  只渲染，只发意图                          │
└──────────────────▲───────────────────────┘
                   │ WebSocket + AnvilProtocol（Zod）
┌──────────────────┴───────────────────────┐
│  apps/host  Node 22                      │
│  工作区 · 信任 · 索引 · Git · PTY         │
│  审批队列 · 编排器 · 进程监督              │
│  PiAdapter（SDK | RPC）                   │
└─────────────▲────────────▲───────────────┘
              │            │
     Pi SDK / RPC     自研 Pi Extensions
     session jsonl    gate / delegate / snap
```

### 8.2 为什么 MVP 不用 Electron

当前最快的迭代路径是本机 Web GUI：Host 起 HTTP+WS，浏览器打开。和 DeepSeek Harness 同类。Electron/Tauri 只在需要托盘、文件关联、安装包时再加薄壳。

**不建议用 Tauri 跑 Host。** Pi SDK 是 Node/TypeScript，Host 必须是 Node，才能零摩擦调用 `createAgentSessionRuntime()`。壳和引擎分离。

### 8.3 与 Pi 的两种接入

| 方式 | 优点 | 缺点 | 何时用 |
|---|---|---|---|
| SDK in-process | 类型完整、事件细 | Host 崩溃带崩 Agent；隔离弱 | 开发默认 |
| RPC sidecar `pi --mode rpc` | 进程隔离、可杀可重启 | 要自己分帧 JSONL（禁用 Node readline） | 发布默认；不信任仓库强制 |

Host 只暴露一个 `PiAdapter`。UI 只认规范化事件 `AnvilEvent`。换接入方式不许改前端。

```ts
interface PiAdapter {
  prompt(input: PromptInput): Promise<void>
  steer(text: string): Promise<void>
  followUp(text: string): Promise<void>
  abort(): Promise<void>
  compact(instructions?: string): Promise<void>
  navigateTree(nodeId: string): Promise<void>
  newSession(): Promise<SessionRef>
  switchSession(id: string): Promise<void>
  fork(entryId: string): Promise<SessionRef>
  subscribe(cb: (ev: NormalizedEvent) => void): () => void
  dispose(): Promise<void>
}
```

`createAgentSessionRuntime()` 在 cwd 变化、new/resume/fork 时会替换内部 `session`。Host 必须在替换后重新 `subscribe`，并重新 `bindExtensions`。

### 8.4 仓库结构

```
anvil/
  apps/web/                  React 工作台
  apps/host/                 Node Host
  apps/desktop/              后期壳，Phase 1 可空
  packages/protocol/         AnvilProtocol 类型
  packages/ui/               设计系统
  packages/pi-ext-gate/      权限闸门扩展
  packages/pi-ext-delegate/  子任务委派扩展
  packages/pi-ext-artifact/  快照与制品扩展
  docs/                      本文件与开发计划
```

### 8.5 技术选型（锁定）

| 项 | 选择 | 不选的理由 |
|---|---|---|
| 语言 | TypeScript 5，ESM | 与 Pi 同语言 |
| 包管理 | pnpm workspace | 单体多包 |
| 运行时 | Node 22+ | Pi 生态要求 |
| UI | React 19 + Vite + Tailwind + shadcn/ui | 迭代快 |
| 前端状态 | Zustand | 轻；真相在 Host |
| 协议 | WebSocket + JSON + Zod | 可校验、可重放 |
| 索引库 | SQLite（Host） | 只做索引，不当会话真相 |
| 测试 | Vitest | Host 对 Pi 先用 FakeAdapter |
| 桌面壳 | 推迟；候选 Tauri 2 或 Electron | 不进 MVP |

Pi 版本 **钉死**，升级当专项。

### 8.6 自研边界

**绝不自研**

- LLM provider 适配
- tool calling loop
- session jsonl / branch / compaction 算法
- extension / skill / template 加载器
- 模型目录刷新

**必须自研**

- 工作区与信任模型
- 事件规范化与时间旅行 UI
- 会话树可视化、多列对比
- 文件快照 / Diff
- 权限闸门
- 多 Agent 编排
- 看板、制品库
- token / 费用 / 失败分类
- 中文 UX 与命令面板

**做成 Pi Extension，不进 Host 内核**

- `beforeToolCall` 审批
- `delegate_task`
- write/edit 前后快照
- `/plan` `/review` `/ship` 等 slash 命令
- 网络搜索、浏览器（可装第三方包）

## 9. 数据与协议

### 9.1 真相分层

| 层 | 内容 | 位置 |
|---|---|---|
| Pi 真相 | 消息、树、compaction、模型 | 项目下 Pi session jsonl，**不改格式** |
| Host 索引 | 标题、项目、标签、费用汇总、树缓存 | `%USERPROFILE%\.anvil\index.sqlite` |
| 工作区策略 | 信任、工具策略、审批规则、角色 | `<repo>/.anvil/settings.json` |
| 制品 | 补丁、报告、截图、快照 | `<repo>/.anvil/artifacts/` |
| 密钥 | API Key / OAuth | 尽量让 Pi 管；Anvil 自有设置进 OS 凭据库 |
| 角色 | persona | `~/.anvil/personas/` + 项目覆盖 |
| Host 配置 | 最近项目、窗口、主题 | `~/.anvil/config.json` |

`.anvil/` 对 Agent **默认不可见**，除非用户显式打开该目录当工作区（不推荐）。

## 10. 多 Agent 模型

Pi 官方跳过 subagent。Anvil 做 **有监督的委派**，不做微服务操作系统。

```
用户
 └─ 主会话 A（角色=指挥/架构师）
      ├─ delegate → 子会话 B（实现者，可限 cwd）
      ├─ delegate → 子会话 C（审查者，只读）
      └─ 汇总：摘要 + 变更文件列表写回 A
```

规则：

- 每个子任务是 **真实 Pi session**（可单独打开）
- 使用 Pi 已有的 `parentSession` 追踪
- v1 委派深度 = 1，禁止孙 Agent
- 共享内存 = 文件系统 + git，不做另套记忆总线
- 同一文件同时写：Host 文件锁，后来者排队或要求换分支
- 子任务有目标、工具白名单、超时、花费上限
- 回写父会话的是摘要，不是全文 transcript

实现落点：Pi extension 暴露 `delegate_task` 工具；真正 `createAgentSession` 由 Host 执行。UI 只画托盘。

内置三角色：

| 角色 | 默认工具 | 职责 |
|---|---|---|
| 架构师 | read | 拆任务、写计划、汇总 |
| 实现者 | read/edit/write/bash | 改代码、跑测试 |
| 审查者 | read | 找问题、不改文件 |

## 11. 安全模型

Pi 文档写明：它没有内置 FS/进程/网络权限系统，默认等于启动用户。Anvil 如果不管，就是给模型 root。

### 11.1 三层闸门

1. **项目信任**  
   第一次打开：只读。用户点信任后才启用写与 bash。
2. **工具策略**  
   按工具 / 命令前缀 / 路径 glob：`allow | ask | deny`。  
   实现点：Pi `beforeToolCall`（`pi-ext-gate`）。  
   UI：审批卡。
3. **进程隔离**  
   开发：SDK in-process + 策略。  
   不熟仓库：强制 RPC sidecar。  
   再进一步：Pi 官方 Docker / Gondolin / OpenShell。

### 11.2 默认保护

- 拒绝读写：`.env*`、`**/*secret*`、`**/*.pem`、`**/id_rsa`、浏览器 cookie 路径
- `bash` 默认 ask；白名单仅只读 git 与测试命令
- `rm -rf`、`git push`、`git reset --hard`、改远程：永远 ask，不允许「允许本会话」一键放行（可在设置里显式关闭，默认开）
- `~/.anvil` 对 Agent 不可见
- 日志不打 prompt 全文、不打密钥
- Renderer 看不到密钥明文

### 11.3 密钥策略

优先复用 Pi 的 `/login` 与环境变量，Anvil **不自造 OAuth**。若做密钥管理 UI，只写入 OS 凭据库，前端只显示「已配置 / 未配置」。

## 12. UX 与文案原则

- 默认语言：简体中文；专业名词可保留英文（Session、Fork、Steer）
- 空状态必须告诉下一步点哪里，禁止空白屏
- 错误信息含：发生了什么、是否可重试、日志在哪
- 危险操作使用明确动词：「允许执行 `git push`」而不是「OK」
- 工具运行超过 3 秒显示耗时；超过 30 秒可取消
- 费用在状态栏持续可见，避免月底惊吓
- 快捷键：`Ctrl+K` 命令面板，`Ctrl+N` 新会话，`Esc` 中止，`Ctrl+Enter` 发送（Windows）

## 14. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Pi SDK 破坏性更新 | 工作台停摆 | 钉版本；adapter 隔离；升级 checklist |
| 权限没做好 | 毁掉仓库或泄密 | Phase 1 必须有闸门；默认 ask bash |
| 做成聊天套壳 | 没有存在理由 | Phase 2 必须上树；Phase 3 必须上委派 |
| 过早 Electron | 浪费整周 | MVP 只用浏览器 |
| 多 Agent 写冲突 | 代码损坏 | 文件锁 + 深度 1 + 子目录委派 |
| Windows PTY | 终端体验差 | Phase 1 不做终端 |
| 自己不用 | 产品假 | dogfood 作为阶段门 |
| 会话格式被「优化」 | 锁死用户 | 兼容性列为发布阻断缺陷 |
